# 導入手冊

給**導入者**看的，不是給使用者看的。技術部署步驟在 `README.md`，
這份講的是「怎麼把它變成客戶願意付錢的東西」。

---

## 這套東西實際在賣什麼

不是賣程式碼——程式碼是 MIT 授權，誰都能拿。

**賣的是三件客戶自己做不到的事：**

| 交付 | 為什麼客戶自己做不到 |
|------|---------------------|
| **盤點** | 他不知道自己哪些事該自動化。要坐下來問出他每天重複做什麼 |
| **接資料** | 他的客戶名單在 Excel、庫存在紙上、報價在 LINE 對話裡。要先整理進 Notion 才有東西可查 |
| **設定與維運** | LINE channel、Cloudflare、API 金鑰、欄位對照。每一步都會卡，而他沒有除錯能力 |

程式碼是交付的**載體**，不是價值本身。價值在於你替他想清楚了什麼該自動化。

---

## 定價思路

**用專案制，不要用月費。**

月費意味著你要扛維運責任——客戶的 LINE 掛了、API 額度爆了、Notion 欄位被他自己改壞了，
半夜都會打給你。專案制交付完就結案，後續要改另外計費。

| 項目 | 說明 |
|------|------|
| 導入專案 | 一次性。含盤點、資料整理、部署、教育訓練 |
| 後續調整 | 按次或按時計費 |
| 客戶自己付的 | Anthropic API、OpenAI、LINE 加購訊息（都是他的帳號） |

**運算成本要講清楚是客戶自己付**，而且金額很小（日常查詢走斜線指令完全免費，
走 AI 的部分一個月通常不到台幣一百）。這對客戶是好消息，也讓你的顧問費看起來合理——
你賣的是判斷，不是運算資源。

## 導入流程

### 第一階段：盤點（半天）

**不要一開始就講技術。** 先問這些：

- 你每天重複回答哪些問題？
- 人在外面的時候，最常需要查什麼卻查不到？
- 哪件事你一直想做但沒時間？

把答案對到功能上：

| 客戶說 | 對到 |
|--------|------|
| 「客人問有沒有貨我要打回公司問」 | 查庫存 |
| 「不知道這個客人上次買什麼」 | 查客戶／查銷售 |
| 「想到什麼事沒地方記」 | 記待辦 |
| 「老師傅的經驗沒人記下來」 | 口述存知識庫 |
| 「不知道排程有沒有跑」 | 查自動化 |

**沒對到的功能就在 `profile.js` 關掉。** 功能少反而好用——指令少、學得會、
Claude 的工具清單短、每則訊息成本低。

### 第二階段：資料整理（最花時間，也最值錢）

這一步決定成敗。**客戶的資料通常不在能查的狀態。**

- 客戶名單在 Excel 各分頁，欄位名稱不統一
- 庫存在紙本或店員腦裡
- 同一個客戶有三種寫法

先整理進 Notion，再對 `profile.js` 的欄位。

> ⚠️ **每個資料庫的欄位名稱都要實際打開來確認，不要假設。**
> 同一個客戶的三個資料庫，欄位可能分別叫「品名」「商品名稱」「產品」。
> 假設它們一樣，查出來就是一片空白，而且不會報錯。

### 第三階段：部署（一小時）

照 `README.md` 走。三個常見卡點：

1. **LINE 後台的「自動回應訊息」沒關** → bot 回一句、罐頭回一句
2. **`wrangler secret put` 在沒有 TTY 的環境跑** → 存成空字串卻印 Success
3. **webhook URL 忘記加 `/line`** → Verify 一直失敗

### 第四階段：教育訓練（一小時）

**只教三件事：**

1. 打 `/help` 看指令
2. 記不住指令就用講的（會花一點錢但一樣通）
3. 按住麥克風講話是最有價值的用法

不要教他 Notion 怎麼改、不要教他看 Cloudflare。他學不會也不需要學。

## 安全責任的界線

**這件事要在合約裡寫清楚。**

這支 bot 查得到客戶姓名、電話、消費紀錄。程式本身有兩道 fail-closed 的驗證
（webhook 簽章 ＋ user ID 白名單），但**部署方式錯了一樣會出事**：

| 風險 | 誰的責任 |
|------|---------|
| 白名單設成別人的 ID | 導入方（部署時要驗證） |
| 客戶自己把 access token 貼到群組 | 客戶 |
| LINE 官方帳號開放被搜尋 | 部署設定，導入方要提醒 |
| 程式邏輯漏洞 | 依授權條款，軟體按「現狀」提供 |

**建議做法：**

- 交付時當著客戶的面測「用別的 LINE 帳號傳訊息 → 沒有任何回應」
- 合約寫明軟體按現狀提供，導入方負責**設定正確**、不承擔資料外洩的連帶責任
- 客戶的資料庫權杖由客戶自己保管，導入方不留副本

> 交付後**不要保留客戶的 API 金鑰**。留著就是把他的風險變成你的風險。

## 什麼客戶適合、什麼不適合

| ✅ 適合 | ❌ 不適合 |
|---------|----------|
| 老闆本人常在外面跑 | 全天在辦公室，電腦就在旁邊 |
| 資料已經有數位化基礎 | 全部在紙本，要從零建檔 |
| 一人決策，不需要多人協作 | 要多人同時用、要權限分級 |
| 有累積知識的動機 | 只想要一個「聊天機器人」 |

**最後一項最重要。** 這套的核心價值是把老闆腦裡的東西倒出來，
如果客戶只是想要個看起來很潮的 AI，做完他不會用，你也拿不到第二單。

---

## 已知限制（先講，不要等客戶發現）

- **一人專用。** 白名單只認一個 LINE user ID，不是多人系統。
- **不建訂單。** 訂單要同步多個系統，手機打錯字沒得檢查，刻意不做。
- **對話記憶只有 1 小時、最近 8 輪。** 隔天問「昨天那個」它不記得。
- **推播有額度。** LINE 免費方案每月 200 則 push，對話回覆才是無限的。
- **Cloudflare Worker 有執行時間限制。** 極慢的查詢可能逾時退回 push。
