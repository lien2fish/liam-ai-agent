# 導入手冊

給**導入者**看的，不是給使用者看的。技術步驟在 `README.md`，
這份講的是「怎麼把它變成客戶願意付錢的東西」。

**範圍：把助理建起來並交付。** 接客戶自己的資料庫是後續另案，見最後一節。

---

## 交付的是什麼

不是程式碼——程式碼是 MIT 授權，誰都能拿。

**是三件客戶自己做不到的事：**

| 交付 | 為什麼他自己做不到 |
|------|-------------------|
| **設定** | LINE channel、Cloudflare、四種金鑰、webhook。每一步都會卡，而他沒有除錯能力 |
| **調教** | 助理的語氣、事業背景、專有名詞。填得好不好，用起來差很多 |
| **教會他用** | 大部分人裝完就不用了。要讓他在第一週真的養成習慣 |

程式碼是載體，價值在你替他把這條路走通了。

---

## 定價思路

**用專案制，不要用月費。**

月費意味著你要扛維運責任——他的 LINE 掛了、金鑰過期了、額度爆了，半夜都會打給你。
專案制交付完就結案，後續要改另外計費。

| 項目 | 說明 |
|------|------|
| 建置交付 | 一次性。含設定、調教、教育訓練 |
| 後續調整 | 按次或按時 |
| 客戶自己付的 | Anthropic API、OpenAI、LINE 加購訊息（都開在他自己的帳號下）|

**運算成本要講清楚是客戶自己付**，而且金額很小——日常打指令完全免費，
走 AI 的部分一個月通常不到台幣一百。

這對客戶是好消息，也讓顧問費看起來合理：**你賣的是判斷與時間，不是運算資源。**

---

## 導入流程（半天到一天）

### 一、問清楚他要它做什麼（一小時）

**不要一開始就講技術。** 先問：

- 你人在外面的時候，最常需要查什麼卻查不到？
- 你每天重複回答哪些問題？
- 有什麼事你一直想記下來但沒地方記？

第三個問題最重要。**這套的核心價值是把老闆腦裡的東西倒出來**——
他的判斷方法、經驗法則、行業眉角。那些打字打不出來，但用講的十分鐘就有了。

如果他答不出第三題，這個案子的價值會少一半，你要先把期待調整好。

### 二、填設定檔（半小時）

打開 `profile.example.js` 複製成 `profile.js`，**當著他的面一起填**：

| 欄位 | 怎麼問出來 |
|------|-----------|
| `business` | 「跟我講一下你們家在做什麼、你最在意什麼」 |
| `tone` | 看他講話的方式。愛講重點的就設更簡短 |
| `vocabulary` | 「哪些字別人常聽錯？」——地名、品名、行業術語 |
| `knowledgeCategories` | 依他的事業線分，不要用預設值 |

`vocabulary` 最容易被跳過，但它決定語音好不好用。**一定要花時間問。**

選用區塊全部留空。留空的功能會自動關閉，指令表也不會出現——
**功能少反而好用**：指令少、學得會、成本低。

### 三、部署（一小時）

照 `README.md` 走。三個一定會遇到的卡點：

1. **LINE 後台的「自動回應訊息」沒關** → bot 回一句、罐頭回一句
2. **`wrangler secret put` 在沒有 TTY 的環境跑** → 存成空字串卻印 Success
3. **webhook URL 忘記加 `/line`** → Verify 一直失敗

### 四、驗收（十分鐘）

**當著客戶的面測這五項**，不要只說「裝好了」：

| 測 | 為什麼要當面測 |
|----|---------------|
| `/help` | 最基本的連通性 |
| 傳語音 | 他最不相信會成功的那一項，成功了印象最深 |
| `/待辦` | 讓他看到東西真的寫進他自己的 repo |
| **用別支手機加好友傳訊息 → 沒反應** | **證明只有他能用。這一項最重要** |
| 講一段行業知識 → 看它歸檔 | 這是他之後會不會繼續用的關鍵 |

### 五、教育訓練（半小時）

**只教三件事：**

1. 打 `/help` 看指令
2. 記不住就用講的，一樣通（會花一點錢）
3. **按住麥克風講話是最有價值的用法**

不要教他改設定、不要教他看 Cloudflare。他學不會也不需要學。

**留一個作業給他**：這週挑一天，在現場講十分鐘你這行的東西進去。
一週後回訪，看他有沒有做。有做的客戶才會有第二單。

---

## 安全責任的界線

**這件事要在合約裡寫清楚。**

程式本身有兩道 fail-closed 的驗證（webhook 簽章 ＋ user ID 白名單），
但**部署方式錯了一樣會出事**：

| 風險 | 誰的責任 |
|------|---------|
| 白名單設錯人 | 導入方——所以驗收一定要當面測「別人傳訊息沒反應」 |
| 客戶自己把 access token 貼到群組 | 客戶 |
| 官方帳號開放被搜尋 | 部署設定，導入方要主動關掉並告知 |
| 程式邏輯漏洞 | 依 MIT 授權，軟體按「現狀」提供 |

**兩條務必遵守：**

- 所有金鑰都開在**客戶自己的帳號**下，不要用你的帳號代開
- 交付後**不留客戶的 API 金鑰副本**——留著就是把他的風險變成你的風險

## 什麼客戶適合

| ✅ 適合 | ❌ 不適合 |
|---------|----------|
| 老闆本人常在外面跑 | 全天在辦公室，電腦就在旁邊 |
| 有想累積下來的經驗與判斷 | 只想要一個「看起來很潮的 AI」 |
| 一人決策 | 要多人同時用、要權限分級 |

**第二項是關鍵。** 這套的核心是把腦裡的東西倒出來。
客戶如果只想要個聊天機器人，做完他不會用，你也拿不到第二單。

---

## 已知限制（先講，不要等客戶發現）

- **一人專用。** 白名單只認一個 LINE user ID，不是多人系統。
- **對話記憶只有 1 小時、最近 8 輪。** 隔天問「昨天那個」它不記得。
- **推播有額度。** LINE 免費方案每月 200 則 push；對話回覆才是無限的。
- **不做需要同步多系統的寫入操作。** 手機打錯字沒得檢查。

---

## 第二階段：接客戶自己的資料（另案）

**不要包在第一次交付裡。** 理由有三個：

1. **客戶的資料通常不在能查的狀態**——名單在 Excel 各分頁、庫存在店員腦裡、
   同一個客戶三種寫法。整理資料的工比裝助理大得多，而且是無底洞。
2. **先讓他用順再說。** 助理都還沒養成習慣就談資料整合，容易做完沒人用。
3. **這是更值錢的第二單。** 第一階段快速交付建立信任，第二階段才是主菜。

技術上不用改程式——`profile.js` 的選用區塊打開就有了，
`worker.js` 一行都不用動。但**欄位對照一定要實際打開資料庫確認**：
不同資料庫的欄位很可能不一樣，猜錯不會報錯，只會查出一片空白。
