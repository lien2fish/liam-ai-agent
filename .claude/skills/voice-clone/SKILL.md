# 克隆聲音做旁白

```bash
~/聲音素材/tts/say.py "要唸的字"                    # 產出 out/say_000.wav
~/聲音素材/tts/say.py "字" -o /path/前綴 --speed 1.0
```

模型＝`mlx-community/Qwen3-TTS-12Hz-0.6B-Base-bf16`，本機 MLX 跑，**不上任何雲端平台**
（聲音是生物特徵資料）。zero-shot 就夠，沒做 fine-tune。M5 Air 上一句約 5 秒。

## 參考音：四個反直覺結論（2026-09-10 A/B 選出，改動前先看）

1. **不要指定 `--lang_code zh`** — 會變成念稿／機器人腔，不指定（en）最自然
2. **參考音的「語氣」決定產出的語氣**，文本寫法影響很小
3. **文本刻意寫成口語反而更差**（「欸跟你講」），照品牌調性正常寫就好
4. **參考音不是越長越好** — 12 秒串接輸給 6 秒單句

現行參考音＝`~/聲音素材/資料集/wavs/utt_0242.wav`
（「全世界第一尾飛上太空的魚，是台灣鯛——太空人真的吃過」）

⚠️ **IndexTTS-2 不用**：咬字較不清、RTF 高，且 README 的 `python -m` 用法是死的
（無 `__main__`，exit 0 卻不產檔）。

## ⛔ 有些詞一定唸錯，而且換參考音救不了

2026-09-11 用 Lien 新錄的 31 句挑四段當參考音（5~5.4 秒單句口語，符合上面第 4 點），
跟現行的 utt_0242 比：

| 參考音 | 4 句測試的錯誤數 |
|---|---|
| 現行 utt_0242 | 6 |
| 新 A／B／C／D | **全部 7** |

**四個都一樣差，而且錯的是同樣那幾個詞。**
⇒ 不是音色問題，是模型對這些字的文字轉音素有問題。**不要再試換參考音這條路。**

### ✅ 有效解法：餵同音替代字

字幕與文案一律用原字，**只有餵給 TTS 的文字替換**。
表在 `~/聲音素材/tts/發音替代表.json`，**`say.py` 預設自動套用**（`--no-fix` 關閉），
命中時會印一行 `🔤 發音替代：現場→線場　…`。

| 原文 | 餵進去 | | 原文 | 餵進去 |
|---|---|---|---|---|
| 現場 | 線場 | | 扶輪 | 服倫 |
| 業務 | 夜霧 | | 經營 | 京營 |
| 旅遊 | 履遊 | | 發布 | 發佈 |
| 漁獲 | 魚獲 | | 忐忑 | 坦特 |
| 真實 | 真石 | | 複製 | 副制 |
| 聲音 | 聲因 | | | |

**實測**：一段同時含這 11 個詞的長句，套用後 `check_say.py` 只報 1 處（清單外的新詞）。

### ⚠️ 要往表裡加新詞時，兩個坑

1. **「業務→頁務」失敗、「夜霧」成功** — 問題出在「**務**」這個字本身，
   只換前面那個字沒用，**要把出錯的字一起換掉**
2. **同音不代表有效** — 旅遊→呂遊（聽成「流油」）、複製→復置（聽成「擴置」）、
   忐忑→袒忒（聽成「坦白」）都同音但都失敗。
   **每一組都要實跑 `check_say.py` 驗過才寫進表**，不能只確認拼音相同

### 還沒解的

蘿蔔（籮蔔、羅蔔都試過無效）、擬、給、能、變。
單字同音選擇少，**建議直接改寫文案**：擬好→寫好、交給→交由、小蘿蔔頭→小朋友。

## 驗收：不要只靠耳朵

```bash
python3 ~/聲音素材/tts/check_say.py <音檔> --text-file <原稿>
python3 ~/聲音素材/tts/check_say.py <音檔> "要檢查的這句話"
```

把產出丟回 Whisper 辨識，用拼音比對原文，分三級：

| 級別 | 意思 |
|---|---|
| 可忽略 | 同音異字、數字轉寫（三十六→36）、Whisper 漏字 |
| 辨識不清 | 拼音只差一兩個字母，多半是 Whisper 沒聽準 |
| 🔴 確定唸錯 | 聲母或韻母真的變了 |

有錯回傳 **exit code 1**，可以接在生成流程後面當品管。

⛔ **對外內容不要只靠耳朵驗。** 聽過很多遍之後會自動把錯的音腦補成正確的字——
2026-09-11 Lien 聽出 2 個，實際有 **15 個**。

**真正重要的片子還是自己錄**（36 歲生日影片最後就是本人錄的）。

## 音量處理（say.py 已內建，`--norm 0` 可關）

處理鏈順序不能換：

```
agate=threshold=-52dB        先壓住安靜段，否則壓縮會把底噪一起拉上來（實測 −68 → −49dB）
acompressor=threshold=-30dB  把弱音提上來，句首落差 17.8 → 7.2dB
loudnorm=I=-16               EBU R128，社群影片慣用
```

⛔ **不要用峰值正規化** — 它只看最大值，管不了段內起伏。
Qwen3 的句首會弱起（「水呢」比同句主體小 17.8dB），聽起來像斷了一下。
⛔ **dynaudnorm 試過更糟**（落差反而變 19.7dB）。

## 接影片時的地雷

⛔ **不可用 atempo 拉長**（放慢）——咬字會糊，Lien 已否決。
要對齊時間軸改調 `data-duration`，不要改 `data-start`。

⚠️ **加快** 風險較低（生日影片用 1.2x 沒問題），但語速是主觀的，
**做完整支之前先給 2~3 種語速的試聽段落讓 Lien 挑**。

⚠️ 混進影片時，**混音鏈上不可放 `loudnorm` 或 `sidechaincompress`**
（會吃掉旁白尾巴／讓旁白相對字幕位移）——詳見 `reel` skill。

## 真人錄音要切成逐句時

⛔ **靜音切分不可靠** — 人的句內停頓常比句間長，門檻怎麼調都對不上
（2026-09-11 實測：1.2s 門檻切出 14 段、0.6s 切出 31 段但全部錯位）。

✅ **用 Whisper 做強制對齊**：辨識出逐字時間戳 → 與腳本做字元序列比對（`SequenceMatcher`）
→ 換算回時間。口誤、多念字、辨識錯字都能容忍（實測字元命中率 94.6%）。

⚠️ 對齊後**還要用能量偵測修邊界**，並**逐段修剪段首靜音**——
兩句連著念時對齊分不開，停頓會被算進下一句開頭
（生日影片最後一句因此夾了 0.42 秒靜音，字幕比聲音早出現）。

可複用的腳本在 `~/Downloads/36歲生日文/製作素材/`：
`asr.py`（轉錄）→ `align.py`（強制對齊）→ `refine.py`（修邊界）→ `build_voice.py`（切段＋變速＋重拼）。
