# 影片產線的工程地雷

自建 ffmpeg 剪輯流程時會踩到的問題。每一條都是渲染完、上傳完才發現的那種——
**修一次的成本是重跑整批**，所以值得先知道。

---

## ⚠️ YouTube「處理中」跑完才說「無法上傳」

最難查的一種：影片本機播放正常、上傳進度 100%、處理也跑完，
**下一步才報錯**，而且不說原因。

通常是把封面卡用 `concat` 壓進開頭造成的。**三個原因缺一不可補齊：**

| 必要條件 | 不做的後果 |
|---------|-----------|
| 正片與封面卡的 `-pix_fmt` `-profile:v` `-level` `-color_range` **完全一致** | `concat -c copy` 只保留第一段的 SPS/PPS，整支用錯的解碼參數 |
| `-movflags +faststart` | moov atom 在檔尾 |
| concat 時**只 copy 畫面、重編音訊**（`-c:v copy -c:a aac`） | 純 `-c copy` 造成接縫 non-monotonic DTS |

實務參數：

```
正片：    -pix_fmt yuv420p -profile:v high -level 4.0 -movflags +faststart
封面卡：  -color_range tv -profile:v high -level 4.0     （scale 加 out_range=tv）
concat：  -c:v copy -c:a aac -movflags +faststart
```

> ⚠️ 這個症狀很容易被誤判成「變速造成 VFR」。**不是**——
> `-r 24` 本來就強制 CFR。往編碼參數一致性查，不要往幀率查。

## 串接外部素材（片頭／片尾）要正規化

直接 concat 別人給的片頭片尾會出三種事：

| 處理 | 不做的後果 |
|------|-----------|
| **音量降到 −12dB** | 外部素材多是 0dB 滿格，正片人聲才 −27dB。**差 11dB 會嚇到觀眾**，平台的響度正規化還會反過來壓低整支 |
| **色彩矩陣轉成跟正片一致** | 外部素材多是 `bt709`，自產的常是 `bt470bg`。concat copy 只保留正片的 SPS，接上去的段落被套錯矩陣解碼而偏色 |
| **timescale 與 profile/level 對齊** | 接縫 non-monotonic DTS |

先偵測來源矩陣，本來就一致時不要多轉一次。

**不要手動 concat**——寫成函式，三件事一起做，漏掉任何一件都會出事。

## Whisper 逐字稿

### 無人聲片段會產生幻覺

對著沒有人講話的段落，Whisper 會吐出 **initial_prompt 的內容**，
或「請訂閱按讚」「感謝觀看」之類根本不存在的句子。

**別當逐字稿用。** 批次轉錄一批素材時，先確認哪幾支是無人聲的。

### 專有名詞一定會錯

同音字、行業術語、地名幾乎必錯。**建一份專案專屬的錯字對照表**（JSON），
在渲染前檢查時自動掃描字幕，踩到新的就往裡面加。

口誤要標註清楚：寫成「正確詞（口誤）」，避免下次校對的人以為是辨識錯誤又改回去。

### 人工校對不可跳過

轉錄 → **人工校對** → 寫 config → 渲染。中間那一步省不了。

## 渲染前檢查，不要渲染後才發現

渲染約 **5 倍實時**——2 分鐘的片重跑一次要 10 分鐘。
寫一支幾毫秒跑完的檢查腳本，**用跟渲染完全同一套時間軸邏輯**
（直接 import，不要複製一份，否則兩邊會漂移）。

該抓的：

| 等級 | 項目 |
|------|------|
| ❌ | 素材檔不存在、是雲端佔位檔、或已被回收 |
| ❌ | 字幕時間碼對不到任何片段（**不會出現在成片**，但不會報錯） |
| ❌ | 指定的高光詞不在字幕字串裡（最常見是空格差異） |
| ❌ | 換行後單行仍超過安全寬度，會貼邊 |
| ❌ | 段落索引或時間碼不合法 |
| ⚠️ | 某段有講話但沒給字幕 |
| ⚠️ | 字幕含已知的辨識錯字 |

---

## 字幕排版

| 項目 | 要點 |
|------|------|
| 安全寬度 | 版面可用寬**扣掉描邊**才是實際可用。900px 的版面配 900px 的字，等於零淨空會貼邊，抓 820px |
| 換行 | 必須**遞迴**換行。只切一刀的話，逗號後半段可能仍然超寬直接衝出畫布 |
| 斷點 | 不切在全形括號內；虛字不落行首 |
| 中文斷詞 | 有斷詞套件就依詞邊界斷，否則會切出「可／以」「客／人」這種 |
| 字型缺字 | `・`(U+30FB)、`／`(U+FF0F) 在部分字型是**豆腐方框**，先自動替換成 `·` `/` |

## ⚠️ 雲端同步會靜默回收素材

磁碟吃緊時，iCloud（及類似機制）會把桌面／文件夾的大檔案回收成佔位檔，
**沒有任何提示**。批次剪輯跑到一半，來源檔變成 0 位元組的 stub，
輸出出來的片段只有幾秒鐘——而 ffmpeg 不會報錯。

| 防護 | 做法 |
|------|------|
| 跑之前 | 確認來源不是佔位檔，必要時強制下載回本機 |
| 跑之後 | 檢查每個中間產物的大小，**小於 10KB 就中止**，不要繼續串接 |
| 長期 | 素材不要放在會被同步的資料夾 |

### 剪片暫存會把硬碟塞爆

每跑一次渲染就在系統暫存區留下整套中間檔案，**而且不會自清**。
實測三天累積 394 份共 23.7GB，把磁碟壓到只剩 146MB——
然後就觸發了上面的 iCloud 回收，連鎖爆炸。

定期查用量並清理，或在流程結束時自行刪除暫存目錄。

## 多來源重組

需要從多支素材抽段重組時，**不要先用 `concat -c copy` 合檔**：
不同來源的幀率（23.98 / 24 / 30）混在一起會漂移。

改成資料結構描述：素材清單 ＋ 段落 `[素材索引, 起, 迄]` ＋ 字幕
`[素材索引, 起, 迄, 文字]`。各段本來就要獨立重編碼再串接，順帶解決混幀問題。

### 聲畫分離（配音蓋圖）

用 A 段的聲音配 B 段的畫面時：

- **以畫面長度為準**：聲音短就補靜音、長就裁掉
- **字幕時間碼要用「聲音來源」的**，畫面來源的時間碼不參與比對，
  否則會出現對不到聲音的幽靈字幕
- ⚠️ 被借畫面的段落**不可有同一人正面說話的嘴部特寫**——對不上嘴型

---

## 音訊處理的哲學要分開

不同類型的素材需要相反的處理，**不要共用同一支工具**：

| 素材 | 處理 |
|------|------|
| 口播、實拍對話 | 降噪 ＋ 音量正規化（把小聲的對話拉齊主講者）＋ 混 BGM |
| 音樂演奏 | **原音直出**：不降噪、不變速、不混 BGM、無字幕。音樂就是內容 |
| 無人聲 B-roll（要自行配音） | 不混 BGM、只做高通濾波。**動態壓縮會把環境雜訊拉爆** |

一支工具塞三種哲學，改其中一條產線會毀掉另外兩條。**寧可複製三份。**

BGM 音量：墊在人聲下約 0.15，但**無人聲時 0.15 會太小聲**，純 BGM 建議 0.38。

> 已成片要改音軌不必重跑渲染：產好新配樂後
> `-map 0:v -map 1:a -c:v copy` 換軌，畫質零損失。
